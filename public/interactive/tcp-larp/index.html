01

Measure delivery

b = D × MSS / max(Tsend, Tack)
B = max(Bcurrent, Bprevious)
Waiting for feedback
Meaning & exact rules

D is the number of segments delivered over the sample interval, not the number in one ACK. Linux supplies the real rate sample; this network uses an approximation. Admit it when D ≥ 4 and T ≥ max(RTTmin / 8, 1 μs), with a positive interval. Only admitted, positive, non-app-limited samples enter the peak filter. Each bucket lasts 2G; B is the maximum of the current and previous buckets. Long gaps clear stale buckets; recovery refreshes the filter timestamp.

02

Read the delay signal

G = max(RTTmin, 1 ms)
θ = max(500 μs, RTTmin / 8)
q = (RTT > RTTmin + θ)
Waiting for feedback
Meaning & exact rules

RTTmin remembers the smallest valid RTT, initialized from the handshake estimate. It never expires in this private version. A missing current RTT makes q false. A new delay event requires q and either no saved delay reference H, or RTT > H + θ. A cut with elevated delay saves H = RTT. RTT ≤ RTTmin + θ / 2 resets H to zero. Thus an unchanged standing queue does not cause a new delay cut on every ACK.

General formulas
Clear: C = max(1.25R, 1.02B)
Queued: C = 1.05R
Eligible adaptive U = max(R₀, R, 1.25B)
R′ = min(C, U)
Meaning & exact rules

Growth requires t − tprobe ≥ G, application demand, no recovery, and no loss/ECN/new-delay branch taking priority. U starts at the launch guess R₀. With adaptive rate, U = max(R₀, R); with learned state, a positive current admitted delivery sample, and q false, U = max(R₀, R, 1.25B). Fixed-rate variants keep U = R₀. Learning requires admitted positive delivery, a current RTT, no application limit and no recovery. Once learned, the private code can extend U without a current RTT. These are ordinary data packets, not separate probe data.

React to congestion

Loss / ECN: R′ = max(Rfloor, 0.70R)
New delay: R′ = max(Rfloor,
min(R, max(0.70R, 0.90B)))
Waiting for feedback
Meaning & exact rules

The first reduction is immediate. Another reduction needs t − tcut ≥ G. Congestion takes priority over growth, even when the cut timer blocks a reduction. Rfloor is 125,000 bytes/s = 1 Mbps. Delay-only backoff can retain 90% of the recent peak; explicit loss or ECN does not use that protection. The private implementation does not latch a blocked event for a later cut.

Meaning & exact rules

R is bytes/s, G is seconds, and MSS is payload bytes per segment. The code clamps the raw result to at least 4 segments, then to the active limit: W = min(limit, max(4, ⌈2RG / MSS⌉)). The launch limit applies until adaptive-flight learning releases it; the simulator then uses a 1,000,000-segment clamp. W is a desired outstanding-data budget. It is not segments per second and it is not a measurement of the true path BDP.

06

Grow the actual window on ACKs

Normal: c′ = max(1, min(W, c + a))
Iafter = Ibefore − a
Waiting for feedback
Meaning & exact rules

c is the actual congestion window, W its target, and a the number of newly acknowledged segments. I is the flight count; the displayed subtraction describes ACK processing before new sends, with any separately detected loss also handled by recovery. An ACK can report several segments. SACK can report data beyond a missing hole, so a need not equal the cumulative ACK-number difference. You can free slots and grow the budget before the whole old window is acknowledged.

Recovery rules (I is the flight count after the ACK/loss accounting):
Early recovery: c′ = min(W, max(I + a, 2)).
Recovery after G: c′ = min(W, max(c + a, I + a)).
Timeout recovery: c′ = max(1, min(W, c + a)).
ECN / CWR: c′ = max(1, min(W, ssthresh, max(c, I + a))).

07

Release the next segment

Pacing gap: Δt = L / R′
Send: (I < c′) ∧ receiver space
∧ data ∧ pacing time reached
Waiting for feedback
Meaning & exact rules

L is the segment payload length in bytes. A full segment uses L = MSS. The ∧ symbol means AND: every condition must hold, including waiting until the next scheduled departure. Pacing schedules individual segments. ACKs free outstanding slots and can grow c; they do not require every packet in the previous flight to arrive first. Linux performs actual transport scheduling and recovery; the teaching engine illustrates those mechanisms.

B = recent delivery peak; R₀ = launch guess; c = actual window; W = target; a = newly ACKed segments; I = flight count. Rates in bytes/s; time in seconds unless labeled. Fractional factors are readable approximations of the source’s integer arithmetic. Path BDP uses the simulator’s known capacity, which LARP does not receive.

What this model does
Controller arithmetic
The rate decisions, recent-peak filter, launch-bound release, window target and ACK-window rules are ported from tcplarp_priv, default branch tcp-larp-lab, revision 91ab20ca7b64f8423dda2f2ecfe917eed9726bc0. The official LARP uses adaptive rate and flight. Source constants and integer rounding are retained within the controls’ numeric range.
Validated against the original C on 6,000 generated state/feedback cases, including rate decisions, window targets and all ACK-window modes. Additional transport checks cover ordering, segment-3 repair, frame-independent timing, receiver limits and the retained private RTT edge cases.
The surrounding network is a teaching model
A FIFO bottleneck, symmetric propagation, receiver ordering, SACK-like receipts and simplified loss recovery make the mechanism visible. Data and ACKs use the same propagation speed; waiting and serialization add delay at the bottleneck. Two-segment/delayed ACKs, sampling intervals, recovery timers, ECN handling and peer controllers are illustrative, not a full Linux implementation. The TCP handshake is assumed complete. The path capacity is known to the simulator, not passed to LARP.
Displayed rates are simulation values, not benchmark measurements. AIMD and CUBIC-style peers illustrate different window policies; they cannot predict native CUBIC/BBR fairness. This is not a QUIC model.
The private version’s edge cases are retained
Its minimum RTT does not expire. Missing current RTT makes the queue flag false and can still allow growth. Congestion notifications inside the cut timer are not retained for a later cut. These are visible in One ACK; the newer public controller’s fixes are not silently added here.
Read the picture
Every visible packet box is one segment. On large paths the renderer chooses a stable sample at transmission time, while the engine counts all segments. A selected box keeps its identity throughout its trip. In the FIFO, boxes shrink into colored tokens; the bottom token is in service. The early lessons use small link values to make individual segments visible. Window bars are budgets, not packets per second. Green receipts travel back to the sender. Orange identifies queueing, drops and repair. Violet belongs to the second sender.
